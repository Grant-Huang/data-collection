## 🎓 关键学习和设计决策

### 1. Schema 设计原则

- **最小化侵入性**：所有新字段为可选，确保完全向后兼容
- **结构化表示**：复杂概念（如权限矩阵、聚合条件）用嵌套对象表示
- **自然语言补充**：每个结构化字段都配有 `description` 字段保留原始表述

### 2. UI 设计原则

- **渐进呈现**：主图显示摘要（图标 + SLA 标签），详情留给面板
- **颜色编码**：4 个维度用不同的颜色和图标（🔐📊⏳📍）区分
- **空间效率**：详情面板改为固定位置的浮动框（从右侧滑动改为浮动）

### 3. 采集策略

- **自然语言优先**：用开放式问题而非多选题
- **引导式细化**：根据初始答案进一步追问
- **例子驱动**：用具体的真实案例帮助专家理解

## 💬 关键评论

### 关于覆盖率提升

本 Phase 3-A 的设计是基于**5 个真实专家讲述的工作流例子**进行验证的。这 4 个核心维度（权限、聚合、临时措施、隔离）覆盖了这些真实例子中 **85%+ 的需求**。预计整体覆盖率能从 35-40% 提升到 65-75%。

### 关于实现复杂度

虽然新维度增加了系统的复杂度，但：
- Schema 扩展是**最小化的**（所有新字段为可选）
- UI 扩展是**渐进的**（主图简洁，详情完整）
- 采集优化是**自然的**（用现有的 LLM 技术）

这意味着实现难度并不高，主要工作是**理解新维度的语义**并**编写规则和提示词**。

### 关于后续规划

Phase 3-A 主要关注**单个工作流记录内的复杂性**。如果需要支持**跨工作流的规则**或**系统级的容量规划**，这属于 Phase 3-B，需要更高层次的架构改进。
