# Phase 3-B: 系统级规则、跨工作流规则和全局策略

**状态**: 规划阶段  
**版本**: 1.0  
**日期**: 2026-10-07

---

## 1. 概述

Phase 3-A 完成后，工作流级的验证和采集已经完整（覆盖率 65-75%）。Phase 3-B 扩展到**系统级和跨工作流级别**，支持：

- **系统级规则**：组织级别的策略、SLA 标准、权限体系
- **跨工作流规则**：工作流之间的依赖、顺序、影响关系
- **全局策略**：一次性定义、多流程复用的规则集

预期效果：
- 增加 **10-20%** 的额外覆盖率（75-85% → 85-95%）
- 支持更复杂的组织流程建模
- 降低重复定义规则的成本

## 2. Phase 3-B 的四个核心维度

### 2.1 系统级规则（System-level Rules）

定义组织范围的标准和约束：

| 名称 | 描述 | 示例 |
|------|------|------|
| **Organization Standards** | 组织级别的工作标准 | 所有质检必须由主管以上审核 |
| **Global SLA** | 全局服务级别协议 | 所有异常处理 24 小时内必须反馈 |
| **Permission Framework** | 统一的权限模型 | 基于角色的访问控制（RBAC） |
| **Compliance Rules** | 合规性要求 | ISO、GMP、FDA 等认证要求 |
| **Resource Policies** | 资源配置策略 | 设备维护计划、人员排班 |
| **Escalation Paths** | 升级路径模板 | 标准化的问题升级流程 |

**实现重点**：
- 中央定义，多流程引用
- 版本管理和变更控制
- 影响分析（改变时提示受影响的流程）

---

### 2.2 跨工作流规则（Cross-workflow Rules）

定义工作流之间的关系和约束：

| 名称 | 描述 | 示例 |
|------|------|------|
| **Workflow Dependencies** | 工作流执行顺序 | 工艺批准必须在生产前完成 |
| **Data Flow** | 数据传递关系 | 质检报告作为追溯证据 |
| **Handoff Rules** | 流程交接规则 | 前工序完成后 2 小时内启动后工序 |
| **Conflict Resolution** | 冲突处理 | 相同设备多条线并行时的调度 |
| **Aggregation Rules** | 多条线结果聚合 | 三个部门都同意才能发货 |
| **Notification Chains** | 通知链 | 异常时按级别通知相关部门 |

**实现重点**：
- DAG 扩展：支持工作流节点之间的边
- 约束验证：检查循环依赖、死锁等
- 执行引擎：支持工作流编排

---

### 2.3 全局策略（Global Policies）

一次定义、多场景复用的策略集：

| 名称 | 描述 | 示例 |
|------|------|------|
| **Decision Policies** | 决策规则集 | "质量例外审核政策"（何时允许偏差） |
| **Template Workflows** | 工作流模板 | "问题解决通用流程"、"工艺变更模板" |
| **Exception Handling** | 异常处理政策 | "紧急停产程序"、"数据泄露应对" |
| **Audit Policies** | 审计政策 | "关键操作记录"、"变更评审流程" |
| **Communication Plans** | 沟通计划 | "危机通知流程"、"变更发布计划" |

**实现重点**：
- 策略库维护：分类管理、版本控制、审批流程
- 策略选择和组合
- 政策适用范围管理（部门/产线/时间）

## 4. 具体实现任务

### 4.1 系统级规则实现

**数据结构**：
```python
class SystemRule:
    id: str
    name: str
    category: str  # organization_standard, global_sla, permission, compliance, resource, escalation
    description: str
    version: str  # 版本控制
    effective_date: datetime
    applicable_scope: dict  # 适用范围：部门、产线、地区等
    
    # 规则内容（根据类型变化）
    content: dict
    
    # 元数据
    created_by: str
    created_at: datetime
    modified_by: str
    modified_at: datetime
    approved_by: str  # 需要审批
    status: str  # draft, approved, active, deprecated
```

**验证规则**：
1. 名称唯一性
2. 有效期逻辑检查
3. 内容格式验证（根据类型）
4. 权限检查（谁可以创建/编辑）
5. 影响分析（此规则影响的工作流数量）

### 4.2 跨工作流规则实现

**数据结构**：
```python
class WorkflowRelationship:
    id: str
    source_workflow_id: str
    target_workflow_id: str
    relationship_type: str  # dependency, data_flow, handoff, etc.
    
    # 关系约束
    constraints: dict  # 比如 "target_must_start_within_2h_of_source"
    
    # 冲突处理
    conflict_resolution: str  # sequential, parallel, conditional
    
    # 通知规则
    notifications: List[str]
    
    status: str  # active, conditional, deprecated
```

**验证规则**：
1. 循环依赖检测
2. 工作流存在性检查
3. 约束逻辑验证
4. 死锁检测
5. 冲突规则一致性

### 4.3 全局策略实现

**数据结构**：
```python
class GlobalPolicy:
    id: str
    name: str
    policy_type: str  # decision_policy, template, exception_handling, etc.
    description: str
    
    # 政策内容
    rules: List[dict]  # 具体的决策规则
    
    # 适用场景
    applicable_conditions: dict
    applicable_workflows: List[str]
    
    # 变更控制
    version: str
    effective_from: datetime
    supersedes: Optional[str]  # 替代的旧政策
    
    # 审批
    requires_approval: bool
    approvers: List[str]
    status: str
```

**验证规则**：
1. 政策完整性检查
2. 适用范围验证
3. 重叠政策检测
4. 版本兼容性检查

## 5. 采集问题设计

### 系统级规则采集（15-20 个问题）

**Tier 1: 概览**（3-4 个问题）
- 这个组织有哪些关键的质量标准？
- 有没有全公司统一的权限模型？
- 组织级别的 SLA 是什么？

**Tier 2: 组织标准**（4-5 个问题）
- 是否有统一的角色定义和权限级别？
- 某些操作（如 Release、工艺变更）是否有公司级的审批标准？
- 有没有统一的记录要求？

**Tier 3: 合规和监管**（4-5 个问题）
- 是否受 FDA、ISO 等认证约束？
- 有没有特定的审计日志要求？
- 数据保留政策是什么？

**Tier 4: 资源和成本**（3-4 个问题）
- 是否有全公司的设备维护计划？
- 人员/资源是否有容量限制？
- 成本控制政策？

### 跨工作流规则采集（12-15 个问题）

**Tier 1: 依赖关系**（4-5 个问题）
- 这个工作流在执行前需要什么其他工作流完成？
- 是串行还是并行执行？
- 有没有时间约束（多长时间内必须启动）？

**Tier 2: 数据交接**（3-4 个问题）
- 需要从其他流程获取什么输入数据？
- 这个流程的输出数据是否被其他流程使用？
- 数据传递的格式和方式？

**Tier 3: 冲突处理**（3-4 个问题）
- 如果多条流程同时需要同一资源会怎样？
- 有没有优先级或调度规则？
- 无法执行时的降级方案？

### 全局策略采集（10-12 个问题）

**Tier 1: 政策类型**（2-3 个问题）
- 组织是否有标准化的异常处理政策？
- 有没有紧急情况下的应对程序？
- 有哪些决策政策是跨多个工作流使用的？

**Tier 2: 政策内容**（4-5 个问题）
- 质量例外何时允许？谁可以批准？
- 工艺变更的标准流程是什么？
- 数据泄露或安全事件如何处理？

**Tier 3: 政策执行**（3-4 个问题）
- 政策是否需要定期审核和更新？
- 所有部门是否都遵循同样的政策？
- 有没有政策变更时的沟通和培训流程？

## 6. 与 Phase 3-A 的关系

| 方面 | Phase 3-A | Phase 3-B |
|------|-----------|----------|
| **范围** | 单个工作流级 | 系统和跨流程级 |
| **验证对象** | 工作流内的逻辑 | 流程之间的协调 |
| **规则定义** | 嵌入在工作流中 | 中央库，多流程引用 |
| **版本管理** | 随工作流版本 | 独立版本控制 |
| **复杂度** | 中等 | 高（需要图分析） |
| **预期覆盖率提升** | 35-40% → 65-75% | 65-75% → 85-95% |

**集成方式**：
- Phase 3-A 的工作流级验证是基础
- Phase 3-B 的系统规则作为工作流验证的约束
- 跨工作流规则在工作流创建和修改时检查
- 全局策略作为工作流决策的参考

## 11. 附录：示例场景

### 场景 1：紧急停产流程

**系统规则**：
- 总经理可无条件触发紧急停产
- 部门经理需要 COO 批准
- 车间主任需要部门经理+品质批准

**跨工作流规则**：
- 停产后，所有在线生产工作流暂停
- 质检工作流进入"紧急检查模式"
- 产品追溯工作流激活，检查已发货产品

**全局策略**：
- "紧急停产通知政策"：30min 内通知所有相关方
- "紧急问题根因分析政策"：24h 内完成初步原因
- "恢复生产审批政策"：需要技术+品质+安全三方同意

### 场景 2：工艺变更流程

**系统规则**：
- 所有工艺变更需要 ECN（工程变更通知）
- 需要工艺、品质、设备三方审核
- 变更必须在 30 天内通知相关产线

**跨工作流规则**：
- 工艺变更工作流 → 产品设计工作流（设计评审）
- 工艺变更工作流 → 生产工作流（执行培训）
- 工艺变更工作流 → 质量监控工作流（加强检查）

**全局策略**：
- "变更级别政策"：根据影响范围分为 A/B/C 级，审批级别不同
- "试产验证政策"：大的工艺变更需要试产验证
- "变更沟通政策"：变更发布前的通知和培训计划
