## 二、新发现的问题

### 发现的事实

通过分析 5 个真实专家讲述的工作流例子，发现了**当前 Schema 无法覆盖的 20 个维度**：

| 类别 | 维度数 | 例子 | 影响 |
|---|---|---|---|
| **决策条件复杂性** | 4 | 聚合条件、上下文 | 核心逻辑缺失 |
| **追溯和范围** | 3 | 多维隔离、量化规则 | 隔离流程无法表示 |
| **权限和签字** | 2 | 多层 release、跨部门 | 采集中最常见问题 |
| **重试和回滚** | 2 | 重试限制、自动失效 | Deviation 管理缺失 |
| **条件激励** | 2 | 测试强度、检查规模 | 检验过程无法调整 |
| **外部数据** | 2 | 认证、历史知识 | 无法表示外部依赖 |
| **临时措施** | 2 | 有效期、失效条件 | 临时方案生命周期缺失 |
| **系统级** | 3 | 容量规划、跨工作流 | 超出单记录范围 |

### 覆盖率分析

```
当前 Schema 覆盖率：35-40%
  ├─ 时间约束：95% ✅
  ├─ 单层评估规则：80% ✅
  ├─ 复杂条件：20% ❌
  ├─ 权限管理：30% ⚠️
  └─ 其他：< 15% ❌

分布对比（真实工作流中）：
  ├─ 权限签字问题：出现在 80%+ 的流程
  ├─ 聚合条件：出现在 40%+ 的决策点
  ├─ 多维范围：出现在 30%+ 的隔离流程
  └─ 其他维度：各 10-20%
```

### 新维度的可信性

✅ **全部 20 个维度都有真实例子支持**（非理论推导）

- 例 1：初评阶段（参数、时间、规则）
- 例 2：测试异常处理（聚合条件、参数分级、强度调整）
- 例 3：设备故障处理（上下文、多维范围、追溯规则）
- 例 4：Deviation 管理（权限、临时措施、重试限制）
- 例 5：变更认证（外部数据、历史知识、跨部门）

## 八、风险和依赖

### 关键风险

1. **权限系统设计过于复杂** → 采集困难
   - 缓解：设计通用模板，简化采集流程

2. **聚合条件的后端计算复杂** → 实现困难
   - 缓解：先做简单聚合（连续N个），复杂的延后

3. **新 Schema 导致现有系统集成困难** → 时间成本
   - 缓解：保证完全向后兼容，逐步迁移
