# Collaborative Workflow Distillation — Paper-Grade Experiment Platform

This package supports Paper 1 experiments for recovering reusable manufacturing micro-workflows from human-agent collaborative work traces.

## New paper-grade modules

### 1. PM4Py baselines

Supported miners:

- `consensus_dfg` — lightweight internal baseline.
- `pm4py_inductive` — PM4Py Inductive Miner.
- `pm4py_heuristics` — PM4Py Heuristics Miner.

Install:

```bash
pip install -r requirements.txt
```

PM4Py is optional at import time. If it is missing, PM4Py runs are reported as unavailable rather than silently replaced by another miner.

### 2. Embedding change-point episode segmenter

Supported segmentation settings:

- `none`
- `heuristic`
- `embedding_cp`
- `oracle`

`embedding_cp` represents every event using activity/capability, intent, actor role, object type, and execution status. It then detects change points from the cosine distance between left/right window embeddings.

Preferred backend:

```text
sentence-transformers / all-MiniLM-L6-v2
```

Fallback:

```text
TF-IDF -> TruncatedSVD -> dense normalized embeddings
```

The fallback makes the experiment reproducible offline and should be reported separately from the transformer-embedding result in a final paper.

## Experimental truth model

```text
M0  Normative Ground-Truth Micro-Workflow
             ↓
     Business Variation
             ↓
MS  Executed Collaborative Work
             ↓
     Execution Deviation
             ↓
     Logging Imperfection
             ↓
ML  Observed AgentNexus-like Event Log
```

Business variation, execution deviation, and logging error are separately parameterized.


The suite compares:

1. Raw + No Segmentation + Consensus DFG
2. Semantic + No Segmentation + Consensus DFG
3. Semantic + Rule Segmentation + Consensus DFG
4. Semantic + Embedding CP + Consensus DFG
5. Semantic + Embedding CP + PM4Py Inductive Miner
6. Semantic + Embedding CP + PM4Py Heuristics Miner

Use at least five independent random seeds in exploratory work and preferably 20+ in final publication experiments.

## Important scientific constraints

- `episode_id_gt` and `microflow_gt` must never be exposed to deployable segmentation or mining algorithms.
- Oracle is an upper-bound setting, not a competing method.
- PM4Py model recovery and episode-boundary recovery should be analyzed separately.
- Transformer embedding and TF-IDF+SVD fallback results should not be pooled as if they were the same method.
- Synthetic results support internal validity and ablation claims but not external validity on real AgentNexus data.

## Recommended final-paper extensions

1. Semi-synthetic traces generated by actual agents interacting with simulated MES/QMS/APS tools.
2. Real AgentNexus traces annotated independently by 2–3 manufacturing experts.
3. Inter-rater agreement (Cohen's kappa / Krippendorff's alpha).
4. 20–30 random seeds and bootstrap 95% confidence intervals.
5. Paired significance tests and effect sizes.
6. Hyperparameter selection using a validation split rather than test-set tuning.
7. Tolerant boundary metrics in addition to exact Boundary F1.
8. Process-mining quality metrics where meaningful: fitness, precision, generalization, simplicity.
9. Cross-scenario and cross-tool generalization experiments.
10. A preregistered primary endpoint to avoid metric cherry-picking.


## Dynamic Experiment Workbench

The UI is now experiment-card based.

- Click **＋ Add Experiment / ＋ 添加实验** to create a new card.
- Click **×** on a card to remove it.
- Cards have a fixed width and are arranged horizontally.
- Approximately 4–5 cards fill a wide desktop screen.
- Additional cards remain in the same horizontal strip and can be reached with horizontal scrolling.
- Click **Run All Experiments / 运行全部实验** to execute all configured cards.

Available experiment-card types:

1. **Base Pipeline**
   - semantic normalization
   - no / rule / embedding / oracle segmentation
   - consensus DFG / PM4Py Inductive / PM4Py Heuristics

2. **Disturbance Ablation**
   - Clean
   - Business Variation only
   - Execution Deviation only
   - Logging Error only
   - Combined
   - Reports marginal Micro-workflow F1 degradation relative to Clean

3. **Robustness Curve**
   - Sweep Business Variation, Execution Deviation, or Logging Error
   - Reports Micro-workflow F1, exact Boundary F1, tolerant Boundary F1, Segment Purity, Fragmentation and Merge Rate

4. **Reusability / Generalization**
   - Holds out one complete scenario composition
   - Discovers micro-workflows on remaining scenarios
   - Reports Case Support, Scenario Breadth, Reuse Diversity, Held-out Event Reuse Coverage and Held-out Composition Coverage

5. **Retrieval Utility**
   - Controlled prospective simulation
   - Compares task execution with vs. without a retrieved micro-workflow
   - Reports task success, steps, tool calls and human interventions
   - This is explicitly a simulation and must not be presented as real AgentNexus production performance.

### Downstream-aware segmentation metrics

The platform now reports:

- Exact Boundary F1
- Tolerant Boundary F1 at ±1 and ±2 events
- WindowDiff
- Segment Purity
- Fragmentation
- Merge Rate
- downstream Micro-workflow F1

These allow the paper to test the hypothesis that **Exact Boundary Accuracy and Downstream Workflow Utility are related but not equivalent objectives**.

## Expert Data Collection Wizard

The app now has two top-level pages:

- `🧪 实验工作台`
- `🧭 专家数据采集 Wizard`

The Expert Wizard is designed for manufacturing experts who do not need to understand AI, event logs, process mining, or micro-workflow terminology.

### Wizard flow

1. Animated explanation: Complete incident → work actions → small-goal grouping → reusable patterns.
2. Case background: problem, operational goal, final outcome.
3. Work trace: one real action per row, preferably 10–30 actions for a complete case.
4. Small-goal grouping: experts group consecutive actions using plain manufacturing language and can explicitly mark ambiguous boundaries.
5. Reusability review: experts judge whether each small work routine can be reused across similar cases, different actors/agents, and different tools/systems.
6. Review and save: the system converts the expert input into a canonical trace schema and registers the case directly in the current experiment session.

### Full-case demonstration

The built-in demonstration is no longer a 3-step toy example. It contains an 18-step production-line breakdown case covering:

- context confirmation,
- root-cause evidence collection,
- production/delivery impact assessment,
- recovery option generation,
- cross-functional review and approval,
- recovery execution,
- recovery verification and closure.

This distinction is deliberate: a 3-step sequence is often already at micro-workflow scale and is therefore too small to serve as a realistic end-to-end case for workflow distillation.

### Direct experiment integration

Cases saved by the Wizard appear immediately in the Experiment Workbench under `专家真实数据快速验证 / Expert Data Quick Validation`.

The current real-data quick validation supports:

- Rule-based segmentation,
- Embedding change-point segmentation,
- No-segmentation baseline,
- Oracle/expert reference upper bound,
- Exact Boundary F1,
- tolerant Boundary F1 at ±1 and ±2 events,
- Segment Purity,
- Fragmentation,
- Merge Rate,
- WindowDiff.

Expert workflow labels remain open-vocabulary and are **not** forcibly mapped into the synthetic eight-microflow catalog. This prevents circular or artificial evaluation of real expert data.

## DAG / Fork-Join Upgrade

The experiment platform now separates **temporal order** from **work dependency**.

### Canonical event fields

- `predecessor_event_ids`
- `branch_group_id`
- `branch_type`: `and` / `xor` / `or`
- `join_policy`: `all` / `any` / `required_set` / `manual_decision`
- `control_role`: `fork` / `branch` / `join`

### Expert Wizard

The Wizard now includes a dedicated **Fork / Parallel / Join** step. Experts answer business-language questions such as:

- “这一步开始前必须等哪些步骤完成？”
- “这些任务是同时都做，还是根据情况选一条？”
- “在哪一步重新汇合？”
- “全部完成后才能继续，还是任意一个结果即可？”

The system converts these answers into DAG control metadata.

### Graph-aware evaluation

In addition to temporal boundary metrics, the platform reports:

- Episode ARI
- Episode NMI
- Pairwise Episode Membership F1
- Edge F1
- Fork Recovery F1
- Join Recovery F1
- Branch Type Accuracy
- Structural Similarity

### New baseline

`consensus_dependency_graph` mines reusable subgraphs from observed dependency edges rather than only directly-follows temporal relations.

`graph_semantic` is a graph-aware work-unit partition baseline that does not require episodes to be contiguous in time.
